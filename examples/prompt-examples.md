# Prompt examples that pair well with a DESIGN.md

With `DESIGN.md` installed in your project root, these prompts produce
on-system UI on the first try. Without one, expect generic output — that
difference is the whole point of this kit.

## Landing page

> Build a landing page for a habit-tracking app. Follow DESIGN.md exactly:
> hero with one primary CTA, a 3-stat strip using the stat component spec,
> and a pricing section with 3 tiers. Use only the colour tokens in the
> file, and respect the Do / Don't list.

## Dashboard

> Build an analytics dashboard: left nav, top bar, 4 stat cards, one line
> chart and a data table. Follow DESIGN.md for tokens, table density and
> number formatting. Numbers must use tabular figures.

## Restyle an existing page

> Restyle `src/pages/settings.html` to match DESIGN.md. Change only visual
> properties (colour, type, spacing, radius, borders) — do not change the
> markup structure or any behaviour.

## New component

> Add a toast notification component following the Components and Motion
> sections of DESIGN.md, including success/warning/error variants and
> reduced-motion behaviour.

## Design review

> Review the current page against DESIGN.md. List every violation with the
> rule it breaks (token, scale step, or Do / Don't item), then fix them.
